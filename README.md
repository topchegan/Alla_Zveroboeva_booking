# Alla_Zveroboeva_booking

Сервис онлайн-записи «Маникюрный салон Алла Зверобоева». Описание продукта — в [CLAUDE.md](CLAUDE.md).

## Запуск

Нужен Node.js 22 (не ниже 22.9).

```bash
npm install
cp .env.example .env   # один раз; затем заполните .env
npm start
```

Откройте http://localhost:3000 (порт задаётся переменной `PORT`).

### Настройка .env в GitHub Codespaces

1. В терминале Codespace выполните `cp .env.example .env`.
2. Откройте `.env` в редакторе и заполните:
   - `ADMIN_EMAIL` и `ADMIN_PASSWORD` — вход администратора «Алла»;
   - `DEMO_PASSWORD` — общий пароль демо-клиентов `irina@example.ru`, `olga@example.ru`, `maria@example.ru`.
3. Запустите `npm start`. Сервер читает `.env` сам (флаг `--env-file-if-exists`, встроен в Node.js).

`.env` не коммитится. Если `ADMIN_*` или `DEMO_PASSWORD` не заданы, сервер запустится,
но выведет предупреждение и не создаст администратора или демо-клиентов. Их можно
дописать в `.env` позже: они создадутся при следующем запуске.

## База данных

SQLite (встроенный `node:sqlite`), файл — `DB_PATH`, по умолчанию `data/app.db`.
При старте сервер сам применяет новые миграции из `migrations/` и заполняет пустые
таблицы начальными данными. Схема описана в [docs/db-schema.md](docs/db-schema.md).

- `npm run db:check` — проверка базы на временном файле (`data/app.db` не трогает).
- `npm run auth:check` — проверка регистрации, входа и сессий на временной базе.
- `npm run booking:check` — проверка расчёта слотов, записи, отмены, переноса и одновременной
  записи на один слот (временная база без демо-записей).
- Начать с чистой базы — остановить сервер и удалить папку `data/`. Демо-записи
  создадутся заново с датами от текущего дня.

## Страницы

| Адрес | Страница |
|---|---|
| `/` | Главная |
| `/login`, `/register`, `/forgot-password` | Вход, регистрация, восстановление пароля (заглушка) |
| `/booking` | Запись: услуга → мастер → время → подтверждение |
| `/booking/success?id=…` | Запись создана |
| `/cabinet` | Личный кабинет |
| `/cabinet/reschedule?id=…` | Перенос записи |
| `/admin` | Админ-панель: записи |
| `/admin/services`, `/admin/masters`, `/admin/blocks` | Услуги, мастера и графики, блокировки |
| `/403` | Нет доступа |

## Вход и регистрация

- Регистрация — имя, email, пароль (не короче 8 символов) и повтор пароля; роль всегда «клиент».
  Администратор создаётся только из `.env` (см. выше).
- Вход по email и паролю; сессия хранится 30 дней в cookie `az_session` (HttpOnly, SameSite=Lax),
  в базе — только хеш токена. После 10 неудачных попыток за 15 минут вход для этого email
  временно блокируется.
- `/booking` и `/cabinet` (включая перенос) открываются только после входа: гостя сервер
  отправляет на `/login` и после входа возвращает на исходную страницу. Администратора `/booking`
  отправляет в `/admin`: записи создают клиенты. Вошедшего пользователя
  `/login` и `/register` отправляют в кабинет (администратора — в админ-панель).
- Шапка строится по текущему пользователю: гость, клиент (с именем) или администратор
  (ссылка «Админ-панель»). На `/login`, `/register` и `/forgot-password` шапки нет — как в макете.
- Защита `/admin` появится на следующих шагах.

API (ошибки — `{ code, message }`):

| Метод и адрес | Что делает |
|---|---|
| `POST /api/auth/register` | `{ name, email, password, passwordConfirm }` → пользователь и сессия; `409 EMAIL_TAKEN` |
| `POST /api/auth/login` | `{ email, password }` → пользователь и сессия; `401 INVALID_CREDENTIALS`, `429 TOO_MANY_ATTEMPTS` |
| `POST /api/auth/logout` | удаляет сессию |
| `GET /api/me` | `{ id, name, email, role }` или `401 UNAUTHORIZED` |
| `GET /api/me/appointments` | записи текущего клиента |

## Запись

Свободное время считает сервер — одна функция `calcSlots` в `server/slots.js`; её же используют
выдача слотов, создание и перенос записи. Правила (CLAUDE.md, п. 8): шаг 30 мин, окно 30 дней,
рабочие дни и часы мастера, визит целиком внутри смены, еженедельные блокировки, действующие
записи мастера, длительность = услуга + дизайн, сегодня — только будущее время, время московское.
Цену и длительность записи считает сервер; значения из запроса не используются.

| Метод и адрес | Что делает |
|---|---|
| `GET /api/salon` | контакты, часы работы салона |
| `GET /api/services` | активные услуги |
| `GET /api/design-option` | опция «Дизайн ногтей» |
| `GET /api/masters?serviceId=&designNails=` | активные мастера, выполняющие услугу (и дизайн) |
| `GET /api/available-dates?masterId=&serviceId=&designNails=` | 30 дней: рабочий ли день, есть ли свободное время |
| `GET /api/slots?masterId=&serviceId=&date=&designNails=` | свободные начала визита |
| `POST /api/appointments` | `{ serviceId, masterId, date, time, designNails }` — только клиент; `409 SLOT_TAKEN` |
| `GET /api/appointments/:id` | своя запись |
| `POST /api/appointments/:id/cancel` | отмена своей записи не позже чем за 24 ч |
| `GET /api/appointments/:id/available-dates`, `GET /api/appointments/:id/slots?date=` | время для переноса (без учёта самой записи) |
| `POST /api/appointments/:id/reschedule` | `{ date, time }` — перенос своей записи не позже чем за 24 ч |

Ошибки: `400 VALIDATION` (неактивная услуга или мастер, мастер не выполняет услугу или дизайн,
неверное число ногтей, дата вне окна), `401 UNAUTHORIZED`, `403 FORBIDDEN` (запись создаёт
администратор), `404 NOT_FOUND` (чужая или несуществующая запись — ответ одинаковый),
`409 SLOT_TAKEN`, `409 TOO_LATE` (до визита меньше 24 ч), `409 ALREADY_CANCELLED`.
Создание и перенос проверяют время в транзакции `BEGIN IMMEDIATE`; если время заняли, пока клиент
подтверждал, страница возвращает его к выбору времени с обновлённым списком слотов.

## Тестовые данные админ-панели (до этапа 3)

Клиентская часть (главная, запись, кабинет, перенос) полностью работает с базой данных.
Админ-панель пока идёт через `public/js/api.js` на тестовых данных из `public/js/mock-data.js`
(файл подключён только на страницах `/admin…`) и хранит изменения в `localStorage` браузера,
поэтому записи в админке и в кабинете пока разные. Админ-панель переводится на API на этапе 3.
